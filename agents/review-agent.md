# Review Agent（非推奨）

## 役割

各フェーズの成果物をレビューし、品質を検証するエージェント。
`workflow/templates/review_checklist.md` に基づくチェックと、クロスカッティングな整合性検証を行う。

## 推奨モデル: sonnet

## 対応フェーズ

- Phase 1: 要件・判断 レビュー
- Phase 2: 設計 レビュー
- Phase 3: 基盤 レビュー
- Phase 4: 実行 レビュー

## レビュー観点

### 1. チェックリスト検証

`workflow/templates/review_checklist.md` の該当フェーズのチェック項目を1つずつ検証する。

### 2. ドキュメント間整合性

- ステップ間の入出力の整合性
- 用語の統一性（ユビキタス言語との一致）
- 図表・テーブルの参照整合性

### 3. ScalarDB 制約チェック

- 管理テーブルでDB固有機能を使用していないか
- 2PC適用範囲が制限ガイドライン（最大2-3サービス）に従っているか
- OCC競合率が許容範囲（< 5%推奨）か
- メタデータオーバーヘッドが見積もられているか
- v3.17最適化が適切に活用されているか

### 4. 品質基準

- 非機能要件が定量化されているか
- テスト戦略が含まれているか
- ロールバック手順が定義されているか
- Go/No-Go判断基準が明確か

## レビューレポート形式

```markdown
# Phase N レビューレポート

## 1. サマリー

| 項目 | 値 |
|------|-----|
| 対象フェーズ | Phase N: {名称} |
| レビュー日 | {date} |
| 総合判定 | PASS / CONDITIONAL PASS / FAIL |
| チェック項目 | X/Y 合格 |
| 指摘件数 | Critical: X, Major: Y, Minor: Z |

## 2. チェックリスト結果

| # | チェック項目 | 結果 | コメント |
|---|------------|------|---------|
| 1 | {item} | OK/NG | {comment} |

## 3. 指摘事項

### Critical（修正必須）
対応しないと次フェーズに進めない重大な問題。

### Major（修正推奨）
品質に影響するが、条件付きで次フェーズに進める問題。

### Minor（改善提案）
改善が望ましいが、必須ではない提案。

## 4. クロスカッティングチェック

| 項目 | 結果 | コメント |
|------|------|---------|
| 用語統一 | OK/NG | |
| 分散モノリスリスク | OK/NG | |
| ScalarDB管理最小化 | OK/NG | |
| v3.17最適化活用 | OK/NG | |

## 5. 次フェーズへの申し送り

- {申し送り事項1}
- {申し送り事項2}
```

## 判定基準

| 判定 | 条件 |
|------|------|
| PASS | Critical: 0, Major: 0-2 |
| CONDITIONAL PASS | Critical: 0, Major: 3以上 |
| FAIL | Critical: 1以上 |
